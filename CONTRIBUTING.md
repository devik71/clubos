# Робимо ClubOS разом

Це локальний сайт-візія, а не підключена операційна система. Усі камери, світло, повідомлення, каса, ціни й файли на інтерактивних сторінках — демодані. Початкові HTML-документи збережені без змін у `public/references/`.

## Перший запуск

Потрібен Node.js 20.9 або новіший (перевірено на 24).

```sh
npm ci
npm run dev
```

Відкрийте http://127.0.0.1:3000. У `/team#start-together` є стартові задачі для світла, пульсу справ, бару й архіву.

Для першого встановлення Claude Code або Codex відкрийте `/start`: інтерактивний посібник українською для Windows і macOS. Він зберігає підтвердження кроків локально в браузері. Команди та джерела містяться в `lib/setup-guide.ts`; інтерфейс — у `components/setup-guide.tsx`.

Перевірка посібника із запущеним локальним сервером на порту 3000: `npx playwright test tests/setup-guide.spec.ts --workers=1`. Тести перевіряють чотири маршрути, збереження прогресу, завершення, мобільну верстку та відмову clipboard/localStorage. Вони не встановлюють CLI на комп’ютер.

## Як працювати з coding-агентом

1. Опишіть знайому проблему та один видимий результат. Наприклад: «слабкий бас не має вмикати групу світла».
2. Попросіть агента прочитати README і цей файл, знайти потрібний компонент та пояснити невеликий план.
3. Зробіть одну зміну. Перевірте її у браузері: звичайний сценарій, помилка, вузький екран і ручний контроль.
4. Запитайте, що змінилося й чому. Якщо пояснення незрозуміле, зменшіть задачу.
5. Покажіть результат технічному провіднику. Зафіксуйте критерій готовності й короткий опис поведінки.

## Перевірка

```sh
npm test
npm run build
```

Для браузерних перевірок: запущений локальний сервер та `npx playwright test`. За потреби встановіть браузер командою `npx playwright install chromium`.

Зберігайте ручний override, явні демопозначки й доступність з клавіатури. Невідомі файли не видаляються; чужі повідомлення не імпортуються без доступу; демо не здійснює оплат і розсилок.

## Наступний етап: Git і Vercel

Коли буде обрано Git-репозиторій, кожна маленька задача йде в окрему гілку, наприклад `light/soft-bass` або `bar/price-update`. Далі — pull request з описом зміни, критерієм готовності й результатами перевірки. Команда переглядає preview Vercel до merge.

Проєкт використовує звичайні налаштування Next.js: install `npm ci`, build `npm run build`. Немає потрібних environment variables чи зовнішніх платних сервісів. Публікація ще не виконана. Перед нею узгодьте доступ до внутрішньої візії; не додавайте реальні чати, контакти й касові дані в публічний репозиторій.
